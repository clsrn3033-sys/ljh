# 목표서 및 완료 판정 기준

| 목표 | 완료 판정 | ver1 상태 |
|---|---|---|
|Pi4B 경량 OS|실제 Buildroot ARM64 이미지 생성·해시 확인|다운로드403으로 차단 |
|부팅5초 목표|전원 투입→사용 가능한 READY를 실기기에서 측정|미측정 |
|800×480 DSI 터치|확정 panel/touch driver·DT·출력/입력 실물 시험|렌더러·입력 어댑터만 모의 확인 |
|디자인 유지|첨부 로고·검정/청록·제작자 정확 표기|사용자 UI 결정·호스트 렌더 확인 |
|자동 백업|순서 판별→용량→복사→독립 검증→sync→정상 unmount|임시 파일·가상 mount 경계 테스트 통과 |
|원본 보존|폴더/파일/XML/SHA-256·메타데이터 검증|기존 엔진 테스트 통과 |
|용량/분리/검증 오류|오류 표시·미완료 보존·성공 오표시 금지|호스트 테스트 통과 |
|설정/센서/RTC|미연결 처리와 설정 재부팅 유지·실물 교정|로직 테스트만 통과 |
|안전 종료|작업 중 예약, 성공·분리 이후 sync/log→OS 종료|mock 경계 통과, 실제 OS 종료 미시험 |
|저전압 보호|실제 BMS/부하 여유에 따른 threshold·신규 작업 제한|로직만 구현, 기본 임계값 미설정 |
|Headless|표시 장치가 없어도 worker 동작|worker 통합 시험 통과, Pi 부팅 미시험 |
|최소 용량|이미지 구성·패키지 목록·최종 바이트 측정|구성만 준비, 새 파일 없음 |
|60FPS 목표|실물 DSI scanout/입력 지연·CPU 부하 측정|미측정. 기본UI 목표30fps |

사진/영상/XML별 별도 분류 규칙과 수동 SD 포맷은 기존 구현이 발견되지 않았고 미구현이다. 현재 원본 구조와 날짜가 포함된 작업 폴더는 보존한다. 포맷을 완성으로 보고하지 않는다. 향후 구현은 검증 성공·장치 identity·원래 filesystem 보존·수동 선택·길게 누름·추가 확인·가상디스크 시험을 전제로 한다.

## 최종 이미지의 출고 조건

실제 이미지 빌드, ARM64 kernel/rootfs 식별, 가상 USB 백업/오류/종료, Pi4B 부팅·DSI·터치·센서·전원 시험과 결과 기록이 필요하다. 이미지 생성만 성공한 상태는 하드웨어 동작 보장이나5초 목표 달성을 의미하지 않는다.
