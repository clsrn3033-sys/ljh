# 다음 기기의 작업 순서

1. `04_인계서.md`의 명령으로 소스·폰트·도구·118개 테스트와 UI 프리뷰를 재현한다.
2. `evidence/network-domains.txt`의 공식 source 접근을 실제 확인한다. 현재 cloud 초안은 저장됐지만 실행 환경의 proxy403은 해결되지 않았다. 접근 가능한 정상 환경에서 빌드하거나 해당 환경의 관리 UI로 허용 설정을 적용한다.
3. 고정한 Buildroot2026.08 소스를 확인하고 `scripts/pi4-dsi-image.sh`를 실행한다. 새로운 실패는 로그를 진단하고 수정 후 재시험한다. 검증 옵션과 예상 해시는 끄거나 바꾸지 않는다.
4. 이미지가 생성되면 raw partition layout, ARM64 kernel, rootfs, MEBS code·로고·폰트, 설정 파티션을 검사하고 크기와 SHA-256을 기록한다.
5. 같은 kernel/rootfs를 ARM64 QEMU에서 부팅하고 테스트용 가상 USB 원본·대상으로 백업·분리·공간 부족·변조·종료를 시험한다. 실물 DSI와 QEMU 출력의 차이를 기록한다. Pi4 이미지를 QEMU raspi4에 넣으면 바로 부팅된다고 가정하지 않는다.
6. 실제 panel/touch controller와 overlay, evdev, backlight 경로를 확인한다. 기본 hardware.json은 미설정이므로 테스트 이미지 빌드만으로 DSI가 표시되는 것은 아니다.
7. INA226 션트·정격·극성,3.3V와 주소, 셀·BMS, 강압기·USB 기동전류, 충전기 power-path를 확정한다. 자료 없이 확인 flag만 true로 바꾸지 않는다.
8. Pi4B 실물 부팅·센서·RTC·설정 재부팅 유지·장시간 백업·전원 여유·READY 시간과 FPS를 측정한다.
9. 미구현 분류 규칙·수동 포맷은 요구를 확인하고 가상디스크로 별도 개발한다. 기존 파일 구조 보존 동작을 임의 변경하지 않는다.
10. 완료 결과와 미실시 항목을 나누어 다음 버전 문서에 기록한다. `.img`는 생성과 검증의 실제 범위를 붙여 제공한다.
