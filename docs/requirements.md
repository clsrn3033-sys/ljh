# 사용자 요구사항과 결정 상태

이 대화에서 제공한 MEBS 개발 지시서가 현재 기준이다. 이전 ChatGPT 대화/이미지에
접근할 수 있는 도구는 연결되지 않았으며 이전 자료를 확인한 것으로 취급하지 않는다.

## 유지할 확정 요구사항

- 기존 GitHub `clsrn3033-sys/ljh` 사용. 빈 저장소에서 신규 구현 허용 받음.
- 최종 Orange Pi 3B V1.1, 초기 Raspberry Pi 4, Buildroot 초경량 Linux/microSD.
- 3.5~4인치 터치 LCD, 무거운 데스크톱 제외. GPIO 안전 종료/전원/포맷 확인.
- MEBS 로고, 제49기 보도부 이정헌, Produced by 이정원(최종 이름 확인 필요).
- 이미지 1장/텍스트/단순 진행률, BACKUP READY, 5초 이내 준비 목표.
- USB 자동 감지, 연결 순서에 따른 역할, 원본 폴더 구조/XML/관련 메타데이터 보존.
- 복사 후 SHA-256 검증, 진행률/상태/실패 표시, 완료 후 안전 분리 절차.
- 원본 자동 삭제와 사용자 확인 없는 포맷 금지. 역할 불명확 시 파괴적 작업 금지.
- 검증 실패는 성공 처리 금지. 강제 종료 손상 방지 및 실물 검증.
- BC250에서 소스 직접 빌드, QEMU 사전 테스트, Pi4 후 Orange Pi 포팅.
- 단계별 수정/테스트 기록. 미검증 성공 보고 금지. 원격 변경은 사전 승인.

## 첫 단계 구현 선택 (최종 하드웨어 사양 아님)

- 호스트와 ARM Linux에서 같은 안전 로직을 시험하기 위해 Python 표준 라이브러리
  엔진 사용. Python 런타임 크기/시작 시간은 Buildroot 실측 후 판단한다.
- 작업별 새 백업 디렉터리. 기존 파일 충돌/원본 삭제/중단 작업 자동 재사용 없음.
- GUI 전 단계로 JSON 진행률 및 터미널 준비 화면 제공. 실제 로고는 넣지 않음.
- 불명확한 연결 순서의 역할은 추정하지 않음. 실제 USB 백업 자동 실행은 아직 없음.
- 메타데이터 보존 불가 시 실패. 파일시스템별 변환/완화 정책은 미확정.

## 별도 확인할 사양

1. 실제 MEBS 로고 파일 및 이전 이미지/지시서. Produced by 최종 이름.
2. LCD 모델/해상도/인터페이스(SPI/DSI/HDMI)/터치 컨트롤러/회전 방향.
3. GPIO 핀/풀업/디바운스/안전 종료 버튼/포맷 버튼/전원 차단 회로.
4. 지원 원본·대상 파일시스템(NTFS/exFAT/FAT/ext4)과 정확한 메타데이터 범위.
5. 연결 순서의 정의, 부팅 전 연결/동시 연결/다중 파티션/허브/재연결 정책.
6. 백업 폴더 명명, 동일 파일 중복·충돌, 증분/전체, 중단 작업 재개 정책.
7. 파일시스템 포맷 종류와 터치/GPIO 확인 절차. 현재 포맷 코드 없음.
8. 5초 측정 시작/종료 지점, 전원 유지 부품 및 손상 허용/복구 기준.
9. Orange Pi 3B V1.1용 U-Boot/커널/BSP 및 저장장치 컨트롤러/디스플레이 지원.
10. 소스 라이선스와 배포 방식. 임의로 공개 라이선스를 부여하지 않음.
